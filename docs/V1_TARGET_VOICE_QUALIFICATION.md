# Enabled Xtensa Voice qualification

## Scope

This adds target checks on top of PR #22's default-off production Voice binding.
It does not change production Voice, Host policy, application provisioning,
Kconfig/default profiles, PCM assets, arena size, DMA, volume or polyphony.
A new root CMake option GM_SYNTH_BUILD_VOICE_LOOP is OFF by default; the
qualification script explicitly sets it ON to define the macro build-wide.
All results must be identified by the tested commit; a submitted workflow is not
passing evidence. Keep runtime_approved=false and all stacked PRs unmerged.

## Builds

`scripts/build_v1_loop_target.sh` builds two separate projects under
`build/v1-loop-target`, with their own sdkconfig paths:

1. The full existing application, explicitly compiled with
   `GM_SYNTH_EXPERIMENTAL_VOICE_LOOP=1`. It still has NO per-Voice plan selection
   or loader/commit orchestration. It is compile/link coverage, not an enabled
   audio product or a hardware long-run result.
2. `tests/idf/loop_voice`, a small ESP32-S3 application using synthetic PCM and
   the real production firmware component. The macro is set build-wide, not
   just on the test file. It deliberately does not need PSRAM, real SF2, I2S,
   an ES8311 or a speaker. Its memory profile is NOT the N16R8 release profile.

The evidence checker inspects every owned C++ translation unit in each compile
command database. It rejects an absent/conflicting/undefined macro, missing/cyclic/oversized/escaping
response files, missing core/app units, native rather than Xtensa compilers, and
non-Xtensa/non-32-bit/non-executable ELF headers. The smoke executable actually
calls the feature, so it cannot pass by only compiling unused inline headers.
GCC response files are expanded with bounded recursion and their hashes retained;
hidden conflicting definitions still fail. Normal builds still default to
macro=0. No normal sdkconfig is modified.

## Execution fixture

`loop_voice_target_cases.h` is compiled for native GCC, native Clang ASan/UBSan
and Xtensa. Its checks do not use assert and remain active with NDEBUG.
72 combinations cover two modes, 16/32/64 source-frame fades, half/unity/1.25
source steps, immediate/32-output-frame release and filtered/unfiltered output.
Every combination checks stale-context rejection with no leaked ref, starts
reference/realtime production Voices, unpublishes the source and resets the
plan BEFORE rendering, then checks exact PCM/phase/finish and final reclaim.
It splits varying block sizes at NoteOff and live gain-update events. The
comparison Voice consumes a pre-rendered stream generated by the frozen cursor.
This reuses that cursor as a transport reference; it does not independently
prove cursor math or assess listening quality. Dynamic LFO/full-FX and real
bank coverage remain with the earlier Host suite, not this 72-case fixture.

The QEMU runner compares exact native/target trace hashes, counts, completion
markers and 32-bit target layout. Missing/duplicate markers or a panic/assert/
WDT line fail even if an earlier PASS appeared. Idle timeout is accepted only
after all required evidence is present. Per-case FreeRTOS yielding avoids
starving idle. The emulator hardware watchdog override is QEMU-only; no
physical firmware watchdog setting is changed. QEMU timings are NOT reported
as ESP32-S3 CPU, I2S deadline or maximum stable polyphony.

## Remaining gates

The tests demonstrate only what their logs actually establish. Real application
plan provisioning, atomic-order program/sidecar commit and retirement, dynamic
Prepare analysis/admission, original-instrument listening, target memory budget,
physical full-FX CPU/DMA/I2S and Crossfade fast paths are separate remaining
work. Nothing here approves the 50 Host candidates for product runtime.
